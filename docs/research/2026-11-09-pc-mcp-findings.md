# MCP-сервер для Raid: Shadow Legends на ПК — находки и решения

Дата: 2026-11-09. Статус: исследование, дизайн ещё не утверждён.

## Задача

Личный инструмент: один игрок, один аккаунт, игра на отдельном Windows-ПК. ИИ-клиент (Claude Code, Codex или другой) управляет игрой через MCP.

Две части:

1. **Рутина сессии** — зайти, Clan Boss, фарм подземелий, сбор наград. RSL Helper умеет крутить повторы боёв, но не переключается между локациями; новый инструмент закрывает связку.
2. **Аналитика аккаунта** — ИИ знает героев, статы, шмот, баффы; подбирает команды из пула и собирает комплекты артефактов под цель (босс/локация), опираясь на руководства из интернета.

## Принятые решения

| Решение | Источник |
|---|---|
| MCP-сервер работает на Windows-ПК рядом с игрой | пользователь (игра на отдельном ПК) |
| Клиент подключается и с Mac по сети, и локально на ПК | пользователь |
| Сетевой транспорт — HTTP в LAN с токеном доступа | предложено, не оспорено |
| Этап 1: ИИ выдаёт план (команда, артефакты, итоговые статы), переодевание — вручную | пользователь |
| Этап 2: ИИ сам кликает в игре | пользователь |
| Мета хранится локально в базе знаний; повторный поиск — только по триггерам | пользователь |
| Нужен скилл для ИИ: метод оценки шмота, расчёт статов, работа с руководствами | пользователь |

### Предположения (не подтверждены)

- RSL Helper остаётся в связке; новый инструмент — «дирижёр» поверх его автоповтора.
- Аналитика приоритетнее рутины.
- Всё локально, без облака, кроме самой модели.
- Риск бана принимается на уровне RSL Helper; собственная инъекция в память игры — нет.
- Триггеры обновления меты: смена версии игры, патчноуты с изменениями героев/боссов, возраст записи старше N дней, явный запрос.

## Находки

### Текущий код репозитория — не подходит

Прототип (май 2025) под Android + Tasker через HTTP→MQTT-мост. Для ПК не применим. Критичные дефекты, если переиспользовать:

- `/messages` — заглушка, SSE-транспорт не получает вызовы инструментов.
- Один `McpServer` на все SSE-подключения.
- Команды публикуются с `retain: true` — повтор старых команд при переподключении.
- Статус читается из двух разных эндпоинтов; `JSON.parse` поверх уже распарсенного axios-ответа.

### RSL Helper

- Закрытый код, только Windows, только GUI. API, CLI, скриптов, плагинов нет.
- Умеет: автоповтор боёв (лимит, до прокачки «еды», до конца энергии с ожиданием), пополнение энергии, автопродажа артефактов по правилам, крафт, Champion Index (герои со статами и баффами), симулятор Clan Boss, калькуляторы, трекеры событий и осколков.
- Не умеет: цепочки задач и переключение локаций.
- Экспорт в CSV упоминается только в рекламном блоге — не подтверждено.
- Champion Index читает данные из игры → автор поддерживает совместимость с текущей версией. Это его ключевая ценность как источника данных.

### Raid Toolkit (RTK) — мёртв

- Последний релиз `v2.8.22.23238` — 2024-02-10, коммитов в основной репозиторий с тех пор нет.
- 2024-08: в issue #131 сообщают о закрытии проекта (объявление в Discord).
- 2026-07: issue #133 — `Metadata version 31 not supported` на игре v151571. С текущей версией игры не работает.
- PR #134 с исправлением закрыт без merge; форк `asultan80` (2026-05) правит пути, но не формат metadata.
- Причина хрупкости: Raid — Unity/IL2CPP, ридер памяти зависит от формата `global-metadata.dat` и ломается на крупных обновлениях.

### agent-desktop (vercel-labs)

- Живой проект: v1.2.0 от 2026-11-05, Apache-2.0, Windows 10 1809+.
- Работает через дерево доступности (UI Automation на Windows), а не через скриншоты; встроенный MCP — только stdio.
- **Raid (Unity), вероятно, не отдаёт элементы в UI Automation** — окно игры будет пустым для ref-подхода. Остаётся `screenshot` + `mouse-click --xy`:
  - требует `--headed` (физическая мышь, ПК занят во время автоматизации);
  - смещение кликов при DPI-масштабировании;
  - если игра запущена от администратора — агент тоже.
- **RSL Helper, вероятно, виден через UI Automation** — можно надёжно управлять его кнопками и, возможно, читать таблицу Champion Index.
- Не проверено на реальной игре и RSL Helper.

### Claude Code на Windows

- Нативно поддерживается (без WSL): Windows 10 1809+ / Server 2019+.
- Установка: `irm https://claude.ai/install.ps1 | iex` (PowerShell) или `winget install Anthropic.ClaudeCode` (без автообновления).
- Git for Windows опционален, даёт Bash; без него — только PowerShell.
- Sandbox на нативной Windows не поддерживается.

## Вытекающая архитектура (черновик)

- **MCP-сервер на ПК**: данные (герои, статы, артефакты, включая неэкипированные) + действия (скриншоты/клики в игре, управление RSL Helper). Транспорты: stdio локально и HTTP с токеном для удалённого клиента.
- **Гибридное управление**: UI Automation для RSL Helper и окон Windows; скриншоты + откалиброванные координаты при фиксированном разрешении окна для игры.
- **База знаний меты**: файл на босса/локацию — роли, пороги статов, сеты, рекомендуемые герои, источник, дата, версия игры.
- **Скилл**: устойчивые правила и метод; меняющуюся мету не хранит.

## Открытые вопросы

1. **Источник данных о героях и шмоте** — главный блокер этапа 1. Варианты:
   - файлы RSL Helper на диске (кэш, БД, экспорт) — проверить на ПК;
   - чтение Champion Index через UI Automation;
   - скриншоты экранов героев (медленно, но независимо);
   - собственный ридер памяти — не рекомендуется.
2. Что реально видит agent-desktop в окнах Raid и RSL Helper.
3. Разрешение/DPI на ПК, запуск игры от администратора.
4. Источники руководств и конкретные значения триггеров обновления меты.

## Следующие шаги

1. Установить Claude Code на Windows-ПК.
2. Разведка на ПК: файлы RSL Helper (`%APPDATA%`, `%LOCALAPPDATA%`, папка установки), snapshot agent-desktop для Raid и RSL Helper.
3. По результатам — выбрать источник данных и написать дизайн-документ.
